"@stoneforge/smithy": patch
---

Merges and post-merge branch sync now handle machine-local live sync state (`.stoneforge/sync/*.jsonl`) that the target branch no longer tracks. `mergeBranch` resolves modify/delete conflicts on those files by deletion instead of failing the merge — a branch-side snapshot of machine-local state is never authoritative — but only when the file is absent from the target tree; genuine content conflicts on files the target still tracks keep failing as before, and a branch whose only changes were sync snapshots reports `alreadyMerged`. `syncLocalBranch`/`syncLocalBranchFromCommit`, when the checked-out target branch's fast-forward is refused by git's overwrite protection and every blocking file is `.stoneforge/` live state the target ref no longer tracks, snapshots the files, cleans them, fast-forwards, and restores the snapshots — leaving them untracked and ignored so every later sync is a plain fast-forward. This unblocks the recurring "local master falls one merge further behind forever" failure in orchestrator workspaces where the dispatch daemon live-writes those files in the main checkout. Conflict-file extraction also now covers modify/delete conflicts, which the previous "Merge conflict in" regex silently missed.
