"@stoneforge/smithy": patch
---

Merges and post-merge branch sync now handle machine-local live sync state (`.stoneforge/sync/*.jsonl`) that the target branch no longer tracks. `mergeBranch` resolves modify/delete conflicts on those files by deletion instead of failing the merge — a branch-side snapshot of machine-local state is never authoritative — but only when the file is absent from the target tree; genuine content conflicts on files the target still tracks keep failing as before, and a branch whose only changes were sync snapshots reports `alreadyMerged`. `syncLocalBranch`/`syncLocalBranchFromCommit`, when the checked-out target branch's fast-forward is refused by git's overwrite protection and every blocking file is a known live-sync path (`.stoneforge/sync/*.jsonl` — deliberately nothing else under `.stoneforge/`, and never still-tracked files like `config.yaml`) the target ref no longer tracks, snapshots the files, cleans them, fast-forwards, and restores the snapshots — leaving them untracked and ignored so every later sync is a plain fast-forward. The whole snapshot/checkout/fast-forward/restore operation holds the new sync-export write lock (`withSyncExportLock` from `@stoneforge/quarry`), so in-process export writers (auto-export ticks, API-triggered exports) are awaited out first and cannot land a write inside the window where the restore would silently destroy it. If a blocking file cannot be read for preservation (or its backup copy cannot be written) the fast-forward aborts before mutating anything; locally-deleted files stay deleted on success and on retry failure alike; snapshots are additionally copied to a temp backup directory that is retained and reported loudly if the restore-after-success fails. `sf daemon sleep`/`wake` now also pause/resume the JSONL auto-export writer, making a sleep a real quiesce of background writers before live-file maintenance. This unblocks the recurring "local master falls one merge further behind forever" failure in orchestrator workspaces where the dispatch daemon live-writes those files in the main checkout. Conflict-file extraction also now covers modify/delete conflicts, which the previous "Merge conflict in" regex silently missed.
